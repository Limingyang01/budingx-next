# SP011 · 团队成员 Worktree 隔离

状态：PLANNED｜更新：2026-11-24｜迭代：SP011。延续[高级能力计划](../../../docs/advanced-capabilities-plan.md#sp011--多代理团队)既定功能。本次以盘点 #39 明确成员隔离和 SP009 通用 Worktree 的边界。细化 AC 为 MODEL_PROPOSED。

## 来源与目标

- USER_CONFIRMED：团队成员 Worktree 隔离进入 SP011（2026-11-24 补排）。
- MODEL_PROPOSED：下列范围与 AC。目标是为并行成员提供互不污染的工作树与分支，并让合并、审查与资源回收有明确授权与可核对结果。

## 范围与非目标

- 范围：为团队成员分配独立工作树与分支；协调成员归属、许可、冲突、审查结果与资源清理。
- 不包含：单会话 Worktree 的创建、进入/切换、退出、合并与清理闭环（属 [SP009 0.9.2 通用 Worktree](../../SP009/tui-gap-optimizations/requirements.md#39-通用-worktree)）；团队任务协调（见[团队任务协调](../task-coordination/requirements.md)）。

## 参考对照

- 参考仓为后台子代理提供 `isolation: 'worktree'`（`src/tools/AgentTool/AgentTool.tsx:99`），并在 swarm 侧回收成员工作树（`src/utils/swarm/teamHelpers.ts:533-544`）。
- 参考仓**没有** `/worktree` 斜杠命令，也**没有** worktree 合并能力；本轮的成员级工作树管理面板与合并均为本仓自研/扩展（合并依据见 [SP009 0.9.2 #39](../../SP009/tui-gap-optimizations/requirements.md#39-通用-worktree)）。

## 验收条件

- **AC-TEAM-WT-01**：两个成员在独立 worktree 并行开发，由第三成员独立审查并运行真实测试。每个成员的读写和 Shell 工作目录一致，彼此和脏主工作区的无关文件与暂存区完整。
- **AC-TEAM-WT-02**：成员变更的源/目标、差异和合并授权可核对。发生竞争、冲突或审批拒绝时安全停止集成；保留待处理结果，避免自动丢弃或推送。
- **AC-TEAM-WT-03**：取消或崩溃重启时按记录回收成员或恢复可见状态，未完成执行先核对，资源删除只作用于已授权且属于本任务的目标。

## 依赖、风险与开放问题

- 依赖：SP009 0.9.2 的单会话 Worktree 绑定持久化、切换与合并（合并为本仓新增）；SP004 的 Git 安全边界（GW-01…09）与删除单次授权；SP010 中期基线。
- 风险：多成员并发操作同一仓库的分支与暂存区是主要破坏面；禁止自动 stash/reset 与未授权推送须在实现层强制，不能只写进提示。成员工作树的回收必须与授权记录一致，避免删到不属于自己的目录。
- 开放问题：**OPEN-1** 成员工作树命名与分支命名规则及冲突处理；**OPEN-2** 成员崩溃后工作树的回收时机（超时、启动时扫描或显式命令）；**OPEN-3** 审查结果由谁核验后允许合并。
