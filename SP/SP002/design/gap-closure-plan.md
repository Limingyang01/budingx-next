# SP002 缺口收尾实施计划

依据：用户 2026-11-17 明确要求按 [缺口报告](../implementation-gap-audit.md) 先 P1、再其余项与测试；沿用已批准设计 v0.3。现有功能分支继续，不重建开发基线、不触碰无关工作区文件。

## 执行顺序

1. P1 模型流程（G01…04/G13）：先用失败测试覆盖 edit/default、凭据交互请求、请求配置路由与探测误报，再实现。Key 通过 `/provider key <档案>` 发起隐藏录入，不接受命令参数中的密钥；新增 `/provider default <档案>`。
2. P1 TUI（G07…09）：测试实际 Ink 输入流；补命令边界队列、粘贴、光标、历史与多行移动、审批 Esc/停打重现/取消清理。
3. P2（G05/06/G10…17）：补 tools 标记、孤儿诊断与显式清理、队列帧同步、工具/notice 保留、宽度订阅、错误分类、超时、可取消重试及非法工具参数回填。
4. 现有和新增测试全部在隔离 home 下运行；本机 HTTP fixture、真实 CLI 子进程、Ink 流交互分别记录，不冒充 live Provider 或人工真终端。
5. 同步 PRODUCT、README、迭代状态与验证报告；运行 npm test、构建/打包 smoke、所属格式检查；审查全部改动，按已批准授权本地提交。具备全部集成前提才按 buding-merge 处理，不推送/发布。

## 决定与验证

- 命令语法为本轮实现选择，用户可见变化同步说明书；不扩展模型自动发现或真实工具范围。
- Provider 在每回合捕获完整配置：当轮内部工具迭代使用同一实例；下轮切换端点与 Key。使用本地双服务验证不串用凭据。
- TUI 基本 resize 改为可重排的内容渲染；不实现全屏虚拟滚动。
- 红绿记录、实际测试数量和未验证边界追加在已有 test-report；本文件复选状态仅在验证后更新。
