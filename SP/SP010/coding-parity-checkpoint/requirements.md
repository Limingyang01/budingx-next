### 目标

用 SP009 的产物（0.9.2 TUI 差距优化、npm 发布工程）做一次中期回归，取得一份**可复现、可交接、可被 SP016 复用**的中期编码效果基线：

1. 把 SP001 已固定的题库规格落成可执行任务、版本化快照与自动断言；
2. 用**真实 Provider + 真实工作区 + 真实权限路径**运行固定任务、盲测任务与保护用例；
3. 核对长任务稳定性与 TUI npm 制品上的行为一致性；
4. 产出中期报告与稳定基线，明确未验证项与恢复条件，交接 SP011–SP014。

- 不实现团队、浏览器、Computer Use、定时任务（SP011–SP014）；不在本轮公布 TUI 还原度覆盖率（SP015/SP016）。
- 不宣称完整替代；不做与原产品的对照运行（O5=B）。
- 不把模型自述完成当作通过依据；不使用旧仓成绩、旧基线或历史轮次结果充当本轮证据。
- 不改产品的用户可见行为来「让测量通过」；测量口径与产品缺陷分别归位（产品缺陷归 [core-reliability](../core-reliability/requirements.md)）。

## 范围

### 1. 中期任务集 v1（CP-SET-v1）

- **分母固定**：18 条基本编码任务 + 12 条保护用例 = **30 条**。基本编码按 SP001 §2 的 8 个类别分布：LOC 2、FIX 4、FEAT 3、TST 3、REF 2、CTX 2、CAN 1、ADV 1；每类 ≥1。语言覆盖 TS / Python / Go / Rust / C# / Java，规模档覆盖 S / M / L，并含 Windows 路径场景。
- **来源约束**：题面与断言**改写**自 SP001 任务清单对应条目（同一类别、同一断言方向），不新增题目语义；题目内容变更按 SP001 §8 追加版本号，不原地改写已发布题目。
- **快照**：每条任务一个 fixture 目录（`scripts/eval/fixtures/<task-id>/`），登记版本号与 SHA-256 清单哈希；同一版本重跑必须得到相同起点；快照不含真实凭据与用户数据。
- **断言**：仅 SP001 §3 的 T / D / X / A / E 方向，且必须可自动判定。
- **盲测批 B1**：基本编码 18 条中 10 条为盲测（满足 SP001 §8「基本 10 条」），失败细节脱敏；本轮修复**不得**依据盲测失败信息。非盲集合 = 基本编码 8 条 + 保护用例 12 条，用于失败分析与修复依据。
- **封版与后续批次**：本轮封版后 B1 进入回归集；为 SP016 预留**新的独立盲测批 B2（≥20 条）**，其中高级组合盲测随 SP015 的 inventory v2 补齐（该缺口登记在交接中，不由本轮填）。

### 2. 测量仪器（评估器）可信化

- 回合上限与产品一致：评估不再注入低于产品的硬截断；预算档按 SP001 §7 锁定并版本化（B = 10 分钟 / 30 轮，A = 20 分钟 / 50 轮，P = 5 分钟 / 10 轮），token 与请求数另设上限；超限判 `BUDGET` 并终止该次运行。
- live 路径支持**真实执行工具**（模型自己跑命令与测试）、**权限档位**（仅可查看 / 工作区内修改 / 完全权限）与**真实审批路径**（含拒绝后继续），使保护用例与真实编码闭环可判定。
- 报告按 SP001 §9 输出：独立任务数、重复运行一致性、按类别分组结果、波动区间（p50/p95）、失败分类分布、token 与费用估算；盲测只出聚合；未测能力清单按本轮范围列出；报告目录与标题按迭代参数化。
- 评估器纳入 `npm test` 的单元测试：清单校验、预算执行、断言求值、统计聚合、盲测脱敏。

### 3. 三类核对

- **基本编码能力**：真实 Provider 在真实工作区运行 CP-SET-v1，每题 ≥3 次重复。
- **长任务**：多步修改 + 上下文压缩 + 恢复 + 中途取消的长会话场景，验证约束不丢、取消后不重放副作用、终态明确。
- **TUI npm 制品**：当前 tarball 隔离安装后完成一次最小真实编码任务，与源码行为对照；记录入口、版本、数据路径一致性。

### 4. 中期报告

- 明确标注**中期结果**，禁止「完整替代」「已对齐」措辞；列出未验证项与恢复条件、失败归因、成本与耗时、以及 SP011–SP014 的输入。

## 依赖、风险与开放问题

- 依赖：SP009 0.9.2 已合入 master（`4252808`、`9be7753`）；`npm run build` 产物；真实 Provider 凭据（`.env.e2e.local`，不入库）；`scripts/spec/check-spec.mjs` 的题库一致性检查继续有效。
- 成本与时长：30 题 × 3 次 = 90 次真实运行，按 SP001 预算档最坏约 15 小时墙钟与真实计费。设计要求**按类别分批、可中断续跑**，并受 `.env.e2e.local` 的请求/费用上限约束；上限耗尽即停止并标 UNVERIFIED，不用无限重试提高通过率。
- 风险：测量口径与产品行为变更耦合（评估器改错会误判产品）。控制方式是评估器单测 + 题目断言基于可观察事实 + 盲测与失败分析分离。
- **OPEN-1**：headless 入口当前未暴露隔离 home 参数（`src/tui/headless.ts` 参数解析仅 `--verbose/--output-format/--input-format/--input-file/--session/--max-turns`）。制品核对若无法隔离用户数据根，改用既有程序化入口或记录 UNVERIFIED，**不在本轮扩参数**（属产品行为变更，另行授权）。
- **OPEN-2**：高级组合任务与高级盲测配额依赖 SP015 的 inventory v2，本轮只登记缺口与 B2 预留位置。
- **OPEN-3**：SP009 短路径补丁 `50e558f` 未合入 master；评估工作区建在临时目录（Windows 上可能是 8.3 短路径），该补丁与本轮测量环境相关，合入方式见[迭代汇总的前置条件](../requirements-summary.md#前置条件与已识别风险)。
