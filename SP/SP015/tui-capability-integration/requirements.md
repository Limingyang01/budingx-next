# SP015 · TUI 能力集成与 P1 收口

状态：PLANNED｜更新：2026-11-24。来源为[正式路线图 P1 出口](../../../docs/iteration-plan.md#tui-还原度要求2026-11-18user_confirmed)与用户补排指令（2026-11-24）。以下细化验收为 MODEL_PROPOSED。

## #12 直接 Shell 输入

在 TUI 提供显式 Shell 输入模式，支持 `!` 入口、Shell 适用的路径/命令补全、与聊天分开的历史和退出反馈。执行复用现有工作目录、权限、审批、输出限制、后台任务和取消路径，命令不会发送给模型。

**偏离声明**：参考仓的 `!` 模式执行时绕过沙箱（`dangerouslyDisableSandbox: true`，`src/utils/processUserInput/processBashCommand.tsx:84,87`），且 `<bash-input>` 文本会随下一轮作为会话消息发给模型（仅 stdout/stderr 被排除出模型输入）。本轮**不沿用**这两点：Shell 执行仍走本仓三档权限与审批，命令与输出均不进入模型上下文。偏离理由：与[能力矩阵](../../../docs/agent-capability-matrix.md)的权限行和「仓内内容不得放宽权限」口径一致。

**参考对照**：参考仓的 Shell 历史与聊天历史**共用同一文件**，靠 `!` 前缀做命名空间隔离（`src/utils/suggestions/shellHistoryCompletion.ts:36-49`）。本轮要求「历史互不串入」，因此需独立命名空间或独立文件，属本仓自研，判据在设计阶段固定。

- **AC-P1-SHELL-01**：在真实 TUI 输入 `!` 后状态可辨，获得 Shell 补全并运行真实只读命令。退出 Shell 后输入恢复为聊天，历史互不串入。命令在当前活动 worktree 的 cwd 中执行。
- **AC-P1-SHELL-02**：拒绝需审批的写命令时无磁盘变更；命令异常退出和用户取消分别可见；长命令和输出遵循既有管理边界，取消后能继续聊天。

## #23 统一设置面板

将 `/config` 从配置回显扩展为可搜索的分页设置面板，复用现有模型、权限等注册命令与面板槽。支持至少一类可编辑的既有配置、修改回显、子面板返回、校验失败反馈和取消时保留原值。既有脚本读取路径和安全配置边界可继续使用。完整主题体系和厂商账户设置单独规划。

**参考对照**：参考仓的 `/config`（别名 `/settings`）是真实可交互面板——多标签页、搜索框、分页滚动与 8 类子面板，40 余项可编辑配置（`src/components/Settings/Config.tsx`）。本仓当前 `/config` 只回显端点/模型/掩码密钥/来源/超时（`src/tui/commands/builtin-config.ts:9-28`），可编辑项来自 `/models`、`/model`、`/permissions`、`/rules` 等既有面板槽，本轮在这些既有入口上扩展，不新建第二套配置存储。

- **AC-P1-CONFIG-01**：在真实 TUI 中进入 `/config`，使用键盘搜索和换页，打开一个既有模型或权限设置子面板。完成一项受支持的设置修改后查看结果并重启，配置仍符合所选值。
- **AC-P1-CONFIG-02**：取消、无效值及写入失败各有反馈，原有配置可用。子面板退出后焦点与选择位置可恢复。敏感值按既有规则遮蔽，非交互配置读取兼容。

## 依赖、风险与开放问题

- 依赖：SP009 0.9.2 的输入编辑（#16）、消息/转录（#20）、后台任务（#36）与 Worktree 绑定（#39）；SP011 的团队任务与成员隔离；SP012–SP014 的高级能力；现有 `/models`、`/permissions`、`/rules` 面板槽与 `/config` 回显实现。
- 风险：Shell 模式触及权限与执行边界，必须复用现有审批、输出上限、后台任务与取消路径，不得新开旁路；设置面板改动配置写入路径，写入失败必须保留原值；两者都属于「可见行为变更」，交付时需同步[产品说明书](../../../PRODUCT.md)。
- 开放问题：**OPEN-1** Shell 补全的词表来源与命中率判据；**OPEN-2** Shell 历史的独立文件还是独立命名空间；**OPEN-3** 设置面板首批可编辑项清单；**OPEN-4** `!` 与既有键位、`/tasks`、审批流程的冲突处理。

全轮团队、浏览器、Computer Use、调度的组合与打包测试继续沿用[高级能力计划](../../../docs/advanced-capabilities-plan.md)。本需求的 AC 均为 UNVERIFIED。
