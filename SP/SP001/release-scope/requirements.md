## 来源与目标

### 用户材料（USER_CONFIRMED）

- `AGENTS.md`：产品版本以 `src/tui/package.json` 为准；发布台账必须有真实回执；npm 一键发布目标由 SP006 骨架化、SP011 完成、SP020 复验全能力制品；**不因编号分配自动获得发布授权**。
- `docs/iteration-plan.md` r3（USER_CONFIRMED 范围）：首批验收默认 Windows 桌面主机、Android/iOS 浏览器远程客户端；原生移动 App 不在范围；跨平台声明以 SP001 的基线盘点与支持矩阵为准。
- 2026-11-16 追加：「基于 node，不要依赖于 bun」。
- 已发布事实：npm 上已有 `budingx` 0.1.0 / 0.1.1（public，MIT），由 GitHub Actions + Trusted Publishing 首发；`latest` 指向 0.1.1。

### 目标

把「这个产品最终以什么形态、在什么平台、用什么运行条件发布」定下来，并把必须由用户拍板的事项列成**明确待决项**，而不是让后续轮次各自假设。

本轮产出**范围定义与待决清单**，不执行任何发布动作。

## 现状（MODEL_PROPOSED，基于本仓实际文件）

- 发布单元：`src/tui`，包名 `budingx`，版本 0.1.1，MIT，`bin: budingx → dist/cli.js`，`engines.node >= 22.18.0`，无运行时第三方依赖。
- 发布链路：`.github/workflows/publish-tui.yml`（master 手动触发、Windows/Linux dry-run 门禁、npm OIDC、只读内容权限、artifact 回执）+ `scripts/release/*`。
- 台账：`release-ledger.json`，记录 `prepared` / `published` 等状态与真实回执。
- 现状产品形态：行式聊天客户端，无工具、无持久化、无无头结构化输出。**当前已发布的包不是「达到原 Agent 水平」的制品**，不得用作该结论的证据。

## 范围与非目标

### 范围

- 制品形态与包名策略（含与已发布 `budingx` 包名的关系）。
- 支持平台矩阵与运行条件（Node 版本、终端要求、模型访问方式）。
- 三端（npm TUI / 桌面 / VSIX）的发布节奏与归属迭代。
- 凭据与用户数据在发布物中的边界。
- 第三方许可与发布内容清单要求。
- 待决项清单（包名、平台扩展、签名与发布账号归属等）。

### 非目标

- 本轮不发布、不改版本、不打标签、不推标签、不动远端设置。
- 不决定具体 npm 包名（列入待决项，给出选项与影响）。
- 不承诺未验证平台的兼容性。
- 不把「已发布 0.1.1」说成完整 Agent 制品已交付。

## 依赖、风险与开放问题

- 依赖：`docs/npm-release-plan.md`（发布工程方案）、`docs/versioning.md`（版本规范）、`skills/buding-npm-release`（发布执行入口）、现有 `scripts/release/*` 与 `.github/workflows/publish-tui.yml`。
- 来源与许可：本仓 `src/tui` 为自有 MIT；未来引入的终端 UI 框架须为 MIT 并登记。
- 风险：
  - 已占用 `budingx` 包名意味着完整 Agent 制品若沿用同名，会覆盖用户已安装的预览版；若换名，则预览版与正式版并存易混淆。必须由用户决策。
  - 平台矩阵若在 SP001 写死而后续无法验证，会产生虚假兼容声明。默认只声明已验证平台。
  - `latest` 标签当前指向预览版；发布范围变更可能影响已安装用户的升级路径。
- 开放问题（决策人：用户）：
  - OPEN-01：**npm 包名策略**。选项 A：沿用 `budingx` 同名升级（用户无感，但预览版用户会收到破坏性升级）；选项 B：新包名（如 `budingx-agent`）并行发布，预览版继续存在（用户需迁移，命名需确认可用性）；默认处理：本轮不选定，按 B 起草并标注待决。
  - OPEN-02：**Windows 之外的平台**。默认：SP001 只声明 Windows 已验证；macOS/Linux 列为「计划中」，SP011 打包工程后逐个验证。
  - OPEN-03：**发布账号与签名归属**。默认：沿用现有 GitHub Actions + Trusted Publishing 路径与现有账号，不新增发布方。
  - OPEN-04：桌面端与 VSIX 的分发渠道（是否上架应用商店）。默认：SP008/SP009 只保证可安装制品，不承诺商店上架。
