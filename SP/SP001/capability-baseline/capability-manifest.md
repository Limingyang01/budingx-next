# SP001 能力清单 v1

状态：v1 已验收（2026-11-16）；v1.2 同步[路线图 r7](../../../docs/iteration-plan.md)｜更新：2026-11-18｜迭代：SP001

## 这份清单是什么

它把「达到原 Agent 的 TUI 水平」从一句形容词变成一张**可勾选、可归属、可验收**的表。每一行是一个能力项（CAP ID），对应原 Agent 已具备的某项用户可见能力；新仓必须逐项给出目标状态、归属迭代和验收方式。

- **不用命令数量、文件行数或功能菜单条目数当达标证据**。清单覆盖度只表示「有没有」，效果强弱由 [评测集](../evaluation-suite/requirements.md) 的任务集判定。
- 覆盖度 = `必交项中验收 PASS 的数量 / 必交项总数`。`建议` 与 `可选` 不进入分母，但进入差距清单。

## 列的含义

| 列 | 含义 |
| --- | --- |
| CAP ID | 稳定编号。已发布版本内的 ID 永不复用、永不改写；废弃项标 `DEPRECATED` 保留行 |
| 层 | L1 交互 / L2 工具 / L3 Agent / L4 平台 |
| 基线证据 | 原 Agent 该能力的存在证据（公开描述或结构观察）。**不含源码、提示词、内部类型** |
| 目标状态 | 新仓达到「同等水平」时该能力应是什么形态。允许与基线形态不同（例如不再 fork 渲染库） |
| 归属 SP | 负责交付该能力的迭代 |
| 验收方式 | 验收层：`逻辑` / `协议fixture` / `真实进程` / `UI` / `live Provider` / `安装` / `人工` |
| 必需性 | `必交` / `建议` / `可选` / `范围外`（保留基线 ID，归属 SP 和当前验收留空） |

## 统计

- 总条目：85
- 必交：47｜建议：22｜可选：9｜范围外：7
- 覆盖度分母固定为**必交 47 项**。建议与可选进入差距清单，范围外仅保留基线身份和变更依据。

## 变更规则

1. 已发布版本的 CAP ID 不复用、不改语义。语义变化必须新增 ID 并标旧 ID `DEPRECATED`。
2. 归属 SP 变更走 `SP/SP001/requirements-summary.md` 的变更记录，不静默改写。
3. 盲测相关能力（CAP-L4-20、SP021 验收能力）的条目在封版后不可修改，只能追加版本。
4. 每轮迭代结束时由该轮负责人更新「当前状态」列，本文件保持版本化快照。
