# 评测集与效果度量 · evaluation-suite

状态：DRAFT｜版本：v1｜迭代：SP001｜来源身份：MODEL_PROPOSED

## 来源与目标

### 用户材料（USER_CONFIRMED）

- 2026-11-16：「实现要求达到 `D:\extra_project\buding-worker-space` 里的 tui 水平」——因此「水平」必须可度量，而不是靠功能清单自证。
- 2026-11-16 决定：基线取证方式为**静态盘点 + 旧仓自证行为**，本轮不运行旧 Agent。

### 目标

定义一套**版本化、可自动断言、含盲测与预算上限**的评测集规范，使「本仓是否达到原 Agent 水平」在后续轮次可以被真实测量，而不是靠功能菜单数量或模型自报完成。

### 与既有规划的关系

`docs/iteration-plan.md`（r3）与 `docs/agent-capability-matrix.md` 已固定以下量（MODEL_PROPOSED，本轮继承不改）：≥30 个基本编码任务 + ≥30 个高级/跨端组合任务；≥20 个独立盲测（基本 ≥10、高级 ≥10）；每题双方各 ≥3 次运行；确定性保护用例全通过；可比集完成率相对原产品下降不超过 5 个百分点。本需求负责把它们变成**可执行的规格**，并补上本轮必须面对的现实约束。

### 本轮必须承认的事实（MODEL_PROPOSED）

**本轮不存在原产品效果基线。** 用户选择静态盘点，不运行旧 Agent，因此：

- 「相对原产品下降不超过 5 个百分点」这条门槛在 SP001 **无法计算**，只能作为后续轮次的门槛条款存在。
- 本轮能交付的是：评测集的**规格、任务清单、断言口径、预算、盲测纪律**，以及本仓自身的可重复测量能力。
- 任何「已对齐原 Agent」的表述在原产品基线缺失时一律不成立。恢复条件写在下面。

## 范围与非目标

### 范围

- 评测任务 schema（每题的必备字段与断言形式）。
- 任务分类法与配额（基本编码 30 / 高级组合 30 / 盲测 20 / 保护用例独立）。
- 评分口径：只按可自动断言的结果，不按模型自报。
- 预算上限（时间 / token / 费用 / 轮数）的初始固定值与调整规则。
- 盲测纪律：封版后不可用于调优；失败分析后另留独立盲测。
- 统计纪律：报告独立任务数与重复运行相关性、关键分组、波动；结果跨门槛记「证据不足」。
- 任务清单本身：60 条任务槽位（标题、类别、语言、仓库规模、断言方向、盲测标记）与 fixture 快照需求清单。

### 非目标

- 本轮不实现评测运行器代码（运行器归 SP002+ 随产品代码建立，属产品代码而非本轮规格范围）。
- 本轮不产出原产品的成功率/耗时/成本数据。
- 不用公开榜单分数替代自有任务集。
- 不在评测过程中降低阈值或删题提分。

## 验收条件

| AC ID | 前置条件 / 输入 | 操作 | 可观察结果 | 验证方式 |
| --- | --- | --- | --- | --- |
| AC-01 | 评测集规格存在 | 检查任务 schema 是否覆盖：初始快照、指令、可自动断言的预期结果、允许修改范围、外部依赖、时间/token/费用/轮数预算、失败分类、盲测标记 | 字段齐全且每项有确定语义 | 人工核对规格 |
| AC-02 | 任务清单存在 | 统计条目数与分类分布 | 基本编码 ≥30、高级组合 ≥30、盲测 ≥20（基本 ≥10、高级 ≥10），且盲测题与调优题不重叠 | 人工核对清单 |
| AC-03 | 任务清单存在 | 检查每题是否有可自动断言的预期结果 | 无「看起来不错」式断言；至少一类为测试/差异/退出码类断言 | 人工核对清单 |
| AC-04 | 任务清单存在 | 检查失败分类是否覆盖：定位错误、修改错误、越权、无效循环、超预算、幻觉成功 | 每类有定义 | 人工核对规格 |
| AC-05 | 评分口径存在 | 检查是否禁止以模型自报「完成」计分 | 明确以测试、差异正确性、用户目标达成为准 | 人工核对规格 |
| AC-06 | 预算表存在 | 检查预算是否为每类任务的固定上限而非运行时无限重试 | 每类有明确上限；超限即判失败并计入失败分类 | 人工核对规格 |
| AC-07 | 盲测纪律存在 | 检查封版后能否修改盲测题 | 明文禁止；变更只能追加版本并另留新盲测 | 人工核对规格 |
| AC-08 | 统计纪律存在 | 检查是否要求报告独立任务数、重复运行相关性、分组结果与波动 | 四项均为必报项 | 人工核对规格 |
| AC-09 | 原产品基线缺失 | 编写本轮结论 | 明确写「无原产品效果基线」，禁止写「已对齐」 | 人工核对 STATUS 与摘要 |
| AC-10 | 保护用例集存在 | 检查是否与盲测分母分开计数 | 保护用例单独列出，不计入盲测分母 | 人工核对清单 |
| AC-11 | 任务清单存在 | 检查 Windows 路径、超大仓库、非英语内容、长上下文场景是否在类别中显式出现 | 四类均有归属任务 | 人工核对清单 |
| AC-12 | 评测集规格存在 | 检查是否规定任务快照版本化与可复现 | 快照带版本号与内容哈希；同一版本可重跑 | 人工核对规格 |

失败/边界场景覆盖：AC-06（超预算）、AC-09（基线缺失）、AC-07（盲测被污染）、AC-02（样本量不足）。

不适用说明：「与原产品同条件对照运行」不适用于本轮，原因见 AC-09。

## 依赖、风险与开放问题

- 依赖：能力清单的任务类别与归属 SP（[能力盘点](../capability-baseline/capability-manifest.md)）；`docs/iteration-plan.md` r3 已固定的量。
- 外部依赖：真实模型访问（live Provider）。本仓无测试凭据，故本轮所有 live 测量为 UNVERIFIED，写明恢复条件。
- 风险：
  - 30 题 × 3 次是起点，不足以自动证明非劣性；结果区间跨越 5 个百分点门槛时必须判「证据不足」，不得只报点估计。
  - 任务集若过度贴近本仓实现会失去泛化性；任务编写须先于对应功能实现，或在实现前冻结任务版本。
  - fixture 快照仓库若与任务分离管理，容易被「改题通过」污染；快照必须带哈希并随任务版本冻结。
- 开放问题：
  - OPEN-01：原产品效果基线的采集授权与时点。默认：SP002 及以后单独申请；不申请则永久 UNVERIFIED，并禁止使用「对齐」措辞。
  - OPEN-02：live Provider 的测试凭据来源与预算上限。默认：使用用户自备凭据，经环境变量注入，不写入仓库；预算上限在 SP002 开始前确认。
  - OPEN-03：高级组合任务（团队/浏览器/桌面/远程/IM/定时）依赖 SP013–SP019 的实现，届时才有可运行环境。本轮只定义题目与断言，不要求立即可跑。
