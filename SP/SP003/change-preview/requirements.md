# 变更预览与撤销 · change-preview

状态：DRAFT｜版本：v0.1｜迭代：SP003｜来源身份：USER_CONFIRMED（路线图功能名与出口门槛）+ MODEL_PROPOSED（AC 切分与预览契约）

## 来源与目标

- 路线图 SP003（USER_CONFIRMED）：功能目录 change-preview；出口「拒绝写入磁盘不变，diff 与实际修改一致，用户无关改动保留」。
- 能力矩阵（USER_CONFIRMED 范围）：CAP-L1-11 Diff 视图（结构化 diff、编辑前后对照；预览 diff 与实际磁盘改动一致）、CAP-L2-02 文件编辑（原子写 + 预览 + 可撤销）。
- 排查文档 SP003 条目（参考事实，仅行为对照）：diff＝hunk + gutter 行号 + 高亮（换 JS 高亮 + Fallback）、窄屏放弃分栏、diff 对话框 list/detail 两级 + current(git)/turn 源切换。
- 当前仓库事实（2026-11-17，`master` = `b0ffc9e`）：仓库尚无 diff 实现，TUI 已用 Ink 8 渲染首屏、状态条与对话流（`src/tui/render/`），无预览对话框。
- 本轮目标：把「即将写入的改动」变成可审阅、可对比、可撤销的结构化对象，并保证预览与真实磁盘结果一致、用户无关改动不被吞掉。

## 范围与非目标

**范围**：结构化 diff 生成（行级 hunk、行号 gutter、增删标记）；预览与实际写入结果的一致性保证；拒绝路径下磁盘不变；写盘前基线校验与冲突拒绝；单文件/多文件改动集合模型；本次会话自身改动的检查点与撤销（撤销冲突时停止自动撤销）；TUI 侧预览对话框（列表 → 详情两级）与源切换（本次会话改动 / 工作区当前状态）；窄屏布局降级。
**非目标**：语法高亮的完整实现（本轮提供最小高亮与纯文本 fallback，高亮不作为验收门槛）；Git 分支/stash/worktree 语义（SP004，本轮源切换只覆盖「本次会话改动」与「工作区当前文件内容」两类来源）；跨会话历史 diff；图片 diff；自动合并算法。

## 验收条件

| AC ID | 前置条件 / 输入 | 操作 | 可观察结果 | 验证方式 |
| --- | --- | --- | --- | --- |
| CP-01 | 两段文本，存在多处增删 | 生成 diff | 输出按 hunk 分组，含旧/新起始行号与行号 gutter；增删行有可区分标记；相同行作为上下文保留且上下文行数有上限 | 单测 |
| CP-02 | 对同一文件先后执行两次修改 | 预览第 2 次改动的 diff，再落盘 | 预览描述的改动与落盘后文件内容的差异一致（对同一基线重放得到相同结果） | 单测 + 真实进程 |
| CP-03 | 权限判定为拒绝（见 permission-controls） | 触发写入并请求预览 | 拒绝后磁盘逐字节不变；预览内容与磁盘仍一致（预览描述的差异未发生） | 单测 + 真实进程 |
| CP-04 | 文件在生成预览后被外部进程修改 | 写盘 | 拒绝写入并说明冲突；外部改动完整保留；本轮不产生任何写盘痕迹 | 单测 |
| CP-05 | 同一文件先被 Agent 改、后被用户改 | 撤销 Agent 的改动 | 只撤销本会话自身可辨识的改动；用户后续改动被保留；无法安全区分时停止自动撤销并提示人工处理 | 单测 |
| CP-06 | 一次回合内修改多个文件 | 查看改动集合 | 改动集合按文件分组，标注新增/修改/删除；撤销按整组或按文件粒度均可用 | 单测 |
| CP-07 | 预览对话框交互 | 打开列表 → 进入详情 → 返回 | 列表项显示文件与增删行数；详情显示 hunk 与行号；可从列表切换到「工作区当前内容」源再切回 | 伪 TTY e2e |
| CP-08 | 窄终端（如 60 列） | 打开预览 | 放弃分栏，退化为单栏纵向布局，内容不截断关键行号 | 伪 TTY e2e |

## 依赖、风险与开放问题

- 依赖：workspace-tools 的写入/编辑能力与基线指纹（提供「预览→落盘」一致性校验所需的旧内容快照）；permission-controls 的判定结果（拒绝时不进入落盘）；TUI Ink 8 渲染层。
- 许可与来源：diff 算法按公开算法（如 Myers 思路）独立实现，不引入第三方 diff 库、不搬参考仓 diff 组件；预览 UI 用 Ink 自绘。
- 风险：行级 diff 在大文件与长行下性能与体积 → 设定 hunk/行数上限并输出摘要；高亮实现易出错 → 高亮仅作增强，fallback 必须始终可用。
- OPEN：预览对话框的默认键位与布局细节在设计阶段确定，并须与既有 TUI 键位不冲突（键位系统整体属 SP006，本轮只占用自有键位并记录）。
