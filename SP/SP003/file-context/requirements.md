# 文件上下文与补全 · file-context

状态：DRAFT｜版本：v0.2（2026-11-17 T18 能力对齐修订）｜迭代：SP003｜来源身份：USER_CONFIRMED（路线图功能名 + CAP-L1-06 必交范围）+ MODEL_PROPOSED（AC 切分与补全交互细节）

## 来源与目标

- 路线图 SP003（USER_CONFIRMED）：功能目录 file-context。
- 能力矩阵（USER_CONFIRMED 范围）：CAP-L1-06「`@` 文件引用与补全」为必交项，验收目标「统一补全层 + 路径补全 + 忽略规则生效」。
- 排查文档 SP003 条目（参考事实，仅行为对照）：@/命令统一 typeahead（5 条 overlay、图标、LCP、目录续补）。
- 当前仓库事实（2026-11-17，`master` = `b0ffc9e`）：TUI 已有自研编辑器层（`src/tui/editor/buffer.ts`、`keys.ts`）与多行/中文输入支持，尚无补全 overlay，也无文件上下文注入。
- 本轮目标：让用户能用 `@路径` 把工作区文件带进本轮上下文，并在输入时获得与命令共用的补全体验；被引用的文件内容以可控体积注入模型。

## 范围与非目标

**范围**：`@` 引用语法解析（路径补全、目录续补）；`@` 与 `/` 命令共用的补全 overlay（候选列表、上下键选择、路径分段完成）；忽略规则在补全候选中生效（被忽略文件不出现）；引用解析后的文件读取与注入（体积上限、截断标注）；引用不存在/越界/被忽略时的可读提示；引用在会话中的呈现（用户与模型两侧都可见被引用了哪个文件）。
**非目标**：多模态图片注入（SP007；本轮图片只给占位与尺寸摘要）；符号/定义跳转与 LSP（SP007 可选）；项目级 CLAUDE 指令文件与记忆（SP005 project-memory / SP006 project-instructions）；MCP 资源引用（SP006）；IDE 选区引用（现行范围外）。

## 验收条件

| AC ID | 前置条件 / 输入 | 操作 | 可观察结果 | 验证方式 |
| --- | --- | --- | --- | --- |
| FC-01 | 输入 `@src/` 后目录含多个文件 | 触发补全 | 候选列表列出该目录下可引用文件（按稳定顺序）；被忽略文件不出现在候选中；可继续逐段补全（目录续补） | 伪 TTY e2e |
| FC-02 | 输入 `@` 后直接接文件名片段 | 触发补全 | 候选按路径匹配过滤；选择后补全为完整相对路径 | 伪 TTY e2e |
| FC-03 | 输入 `/` 命令前缀 | 触发补全 | 与 `@` 共用同一 overlay 与交互（上下键、选择、取消），候选为已有命令 | 伪 TTY e2e |
| FC-04 | 引用工作区内存在的文本文件 | 提交本轮 | 文件内容作为上下文注入本轮请求；内容超过上限时截断并标注；用户侧可见引用了哪个文件 | 单测 + 真实进程 |
| FC-05 | 引用不存在文件 / 工作区外路径 / 被忽略文件 | 提交本轮 | 明确提示对应原因，不静默忽略；不读取工作区外内容 | 单测 |
| FC-06 | 引用图片文件 | 提交本轮 | 本轮按占位与尺寸摘要处理（不假装已读图像内容），并说明图像内容尚未注入 | 单测 |
| FC-07 | 引用文件在引用后被修改 | 下一轮再次引用 | 每次引用读取当时磁盘内容，不缓存旧内容 | 单测 |
| FC-08 | 引用写作 `@路径#L10-20` | 提交本轮 | 只把指定行范围带入上下文（行号 10–20），其余行不注入 | 单测 |
| FC-09 | 补全候选多于一个且存在公共前缀 | 按 Tab | 先补到最长公共前缀而非直接应用某个候选，可继续细化 | 伪 TTY e2e |

## 依赖、风险与开放问题

- 依赖：workspace-tools 的路径解析、忽略规则与读取能力（直接复用，不重复实现）；TUI 编辑器层补全钩子。
- 许可与来源：补全 overlay 用 Ink 自绘，候选逻辑独立编写；不搬参考仓 typeahead 组件。
- 风险：候选扫描在大仓造成卡顿 → 限制扫描深度与条目数，按目录分段续补避免全仓扫描；注入体积膨胀上下文 → 设定注入上限并截断标注。
- OPEN：注入位置（作为用户消息前置上下文块）与默认上限在设计阶段定稿。
