# task-planning · 任务计划与追问

状态：**文档修订待确认**｜版本：v0.3｜依据：路线图 SP004、参考 TUI `b5c9be8`、[设计 v1.3](../design/design.zh.md)

## 目标

多步骤任务可拆解、可展示进度、可更新；计划与待办是**两个独立对象**（计划有 id 与依赖、待办为 `{content, status, activeForm}`）；计划**持久化**为会话隔离的 `.md` 文件；**建议不等于批准**，批准前不自动执行写操作；批准可携带**用户编辑后的计划**，拒绝必须带反馈；缺关键输入时以**多题结构**追问，可取消。

## 边界

- 交付计划状态机与持久化、待办清单、计划模式权限档位、计划审批与执行前校验、追问工具。
- 不做 `/plan` 等斜杠命令的完整交互面（属 SP006 TUI 体验主战场）；本轮交付工具与契约，TUI 侧交付本轮局部场景及交互。
- 不做记忆/压缩对计划的影响（SP005）；跨进程恢复属 SP005。
- **计划模式的语义**：是**权限档位**（写/执行类降级为需批准），**不是**硬阻断——与参考一致（见设计 §9.1 F-11）。

## TUI 与本轮验收

计划审批、待办和追问分别按 VIS-02、VIS-03、VIS-04 验收。使用同一状态表和工具调用 ID，按终端快照与按键回放核对。 统一基线、证据及恢复条件见[验收报告](../test-report.md)。独立来源和 AST 复核见[设计 §9.8](../design/design.zh.md#98-独立实现与-ast-复核)。

## 验收条件（AC）

- **TP-01** Given 多步骤任务，When Agent 提交计划，Then 计划以有序步骤与状态（pending/in_progress/completed/blocked）保存，并可查询。
- **TP-02** Given 计划存在，When 步骤状态变化，Then 计划进度同步更新，阻塞步骤可标记依赖（blocked by）；**待办与计划为两个独立对象**，待办项无 `blockedBy` 且状态仅 3 个。
- **TP-03** 调研状态允许底层准许的只读操作；写入和执行在通过硬性策略后逐次批准。待批期间拒绝并发副作用，退出时恢复原档位。
- **TP-04** ExitPlanMode 读取当前会话计划文件。批准可携带用户编辑正文并重算指纹；拒绝回填反馈，取消结束等待；只有批准或显式退出调研时恢复档位。
- **TP-05** Given 计划被批准，When 执行开始，Then 执行前校验计划与当前仓库/工作区状态一致（目标文件仍存在、基线未漂移），不一致则拒绝执行并说明漂移项。
- **TP-06** Given 缺少关键输入，When Agent 发起追问，Then 以**多题结构**（1–4 题，每题含 `header` 与 2–4 个选项，支持多选）呈现并等待用户选择或自由回答（Other 选项由宿主自动提供）。
- **TP-07** 宿主回答以题目文字为键，答案及备注经原 call ID 的一个工具结果进入历史及下一 Provider 请求。
- **TP-08** 取消以原 call ID 返回一个取消结果并结束等待，迟到、重复及跨回合响应无效。
- **TP-09** Given 计划全部步骤完成，When 查询进度，Then 报告实际完成步骤与残留项，不虚报。
- **TP-10** Given 计划状态，When 会话结束，Then 计划**持久化**为会话隔离目录下的 `.md` 文件（会话内可查、可再读），跨进程恢复属 SP005。

## 开放问题

- OPEN-01：计划审批的交互载体。默认方案：**走权限弹窗通道（复用 SP003 `ApprovalGateway`）+ 计划审批面板**，完整斜杠命令面留 SP006。
- OPEN-02：计划步骤数量上限。默认方案：**单计划最多 50 步**，超出时拒绝并要求拆分；可配置常量。
- OPEN-03：计划文件是否支持「用户编辑后重新指纹」。默认**支持**（对齐参考 F-13 的 `planWasEdited`），编辑后重算指纹。
