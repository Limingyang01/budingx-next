## SP013 · 多代理团队

| 功能目录 | 必交功能 | 验收 |
| --- | --- | --- |
| team-lifecycle | 创建团队、角色/成员模型、成员退出/重启、可观察生命周期 | 至少 3 个真实成员运行；父/成员退出和重启后无孤儿执行；权限不大于发起者，费用和并发上限生效。 |
| task-coordination | 任务拆分、依赖、分配/认领、状态、租约及交接 | 两成员同时抢同任务只有一个持有执行权；崩溃租约过期可恢复；结果未验证不能标完成；依赖失败阻止后续执行。 |
| team-messaging | 点对点/广播消息、持久化游标、结果引用 | 重投/乱序/断连不丢必需消息或重复执行；不同团队/项目消息隔离；消息内恶意指令不能提升权限。 |
| worktree-isolation | 独立工作区、冲突检测、集成结果和资源清理 | 脏主工作区不改动；独立开发+独立审查的真实任务完成；冲突明确停止自动合入；只清理获授权且属于本任务的资源。 |

整轮实战：并行实现两个有依赖的功能，由第三成员审查并执行真实测试；覆盖取消全队、单成员超时、模型限流、重复结果和重启恢复，不用模拟请求冒充团队运行。

## SP017–SP018 · 四类 IM（暂缓 DEFERRED，r6）

**用户 2026-11-17 决定暂缓；编号保留不回收，移出当前依赖与验收分母。下文保留作恢复储备，恢复须用户另行决定且不降门槛。**

公共功能包括适配接口、入站验证、账号/群与项目会话绑定、路由、消息/附件、审批、取消、重试、限流、重启恢复、解绑和凭据保护。SP017 交付基础及 Telegram/飞书；SP018 交付微信/钉钉及跨渠道验证。

| 功能目录 | 独立验收 |
| --- | --- |
| im-adapter-contract / identity-binding | 不同群/用户/平台身份不串会话；伪造/重放/越权入站拒绝；解绑立即阻止新请求，旧待审批失效。 |
| telegram / feishu / wechat / dingtalk | 每个渠道分别以真实账号跑：绑定→选择项目→提问/编码→工具审批→结果回传→取消→解绑；每个都有文本/附件、长输出、重复投递、限流、重启用例。 |
| im-cross-channel | 同会话跨端观察与控制权符合 SP016；群内他人不能批准发起者的动作，过期审批不能执行；一次通知失败不重做编码任务。 |

接入必须固定公开、获授权且可维护的方式、账号类型、权限和平台限制；微信的实际接入模式尤其需验证。账号/平台不可用时记 BLOCKED/UNVERIFIED，不用 mock 或一个渠道代替其他渠道。仅能“收消息”而不能审批/取消不能验收。

## SP019 · 定时任务

| 功能目录 | 必交功能 | 验收 |
| --- | --- | --- |
| schedule-management | 一次性/周期、时区、启停、修改/删除、下次运行 | 时间解析和用户所选时区一致；DST 重复/缺失时间、月末/闰日有固定时钟用例；修改/删除后旧触发失效。 |
| durable-scheduler | 持久化、租约、并发上限、错过触发和重试策略 | 两个执行器/重启/重复事件不并发重复启动同一 occurrence；恢复核对结果，不宣称外部副作用能普遍 exactly-once；错过任务的跳过/补跑策略可观察。 |
| scheduled-agent-run | 绑定 workspace/模型/权限/预算、日志、通知和取消 | 无人值守只使用显式授权；需要新审批则暂停/失败并通知，不无限等待或越权；权限撤销、模型删除、主机离线有明确结果；通知失败不重跑副作用。 |

TUI/headless 提供任务管理入口；Desktop/VS Code/H5/IM 入口随对应暂缓轮移出（r6），调度器契约保留扩展点供恢复时接入。关闭客户端不等于调度器仍在线，独立 Node 执行服务及 offline 状态须明确。调度器不依赖任何 UI 常驻，初期不静默安装系统后台服务。

## SP020–SP021 · 组合、交付与最终验收（当前范围：TUI + 保留高级能力）

- SP020 用同一组角色/权限与运行事件在 TUI/headless 宿主整合团队/浏览器/CU/调度，不复制团队/工具循环；同一权限/取消/恢复用例在交互与无头入口行为一致。
- 干净 Windows 的 TUI/npm 全能力包与独立调度执行器必须有明确制品与安装文档；浏览器与原生资源采用公开可重现来源，离线/下载失败可诊断，Node-only 不等于所有能力无需辅助资源。Desktop/VSIX/网关/IM 制品随暂缓轮移出（r6）。
- npm tarball 不依赖仓库路径、开发依赖、Bun 或已安装的另一客户端；原生或浏览器可选资源的安装/版本/完整性声明明确，并在实际制品上验证。SP011 轻量包的通过不能代替 SP020 全能力包通过。
- 必交组合任务（r6 当前范围）：团队开发+审查+测试；浏览器复验代码变更；桌面应用操作并中途急停；定时任务在重启后继续并经本地/headless 回执通知且不重放已完成修改。手机 H5 与四 IM 组合随暂缓轮移出，恢复时补回。
- 开轮前以 inventory v2 补齐当前范围高级任务与盲测配额（高级 30 / 高级盲测 10；v1 的 REM/IM 11 题含 4 题高级盲测已批注暂缓）。
- SP021 按路线图的扩充任务集逐组以自有测量验收（O5=B），建议连续两轮全量回归及至少 5 个工作日真实工作试用；任何当前必交能力 FAIL/UNVERIFIED、分组未达门槛或效果证据不足，都不能宣称完整替代；暂缓能力单列 DEFERRED。

所有权限/性能阈值是提议，开轮固定后不可为通过降低。资源/账号受限是验收阻塞，不是移除正式范围的理由。用户当前只授权规划高级能力，不授权自动建后台服务、接入真实 IM 或执行屏幕/远程操作。
