# 产品目标与待确认项

## 用户已确认的方向

- 做成自己的作品，逐步剥离没有明确再发行授权的旧 Agent 实现。
- 新项目统一使用 Node.js + TypeScript，产品和维护流程不依赖 Bun；默认主分支 master。
- TUI 单端交付（路线图 r7）：Desktop、VS Code、远程/H5 与四类 IM 移出当前 SP。SP010 保留通用宿主边界。
- 架构保留多端接入入口：宿主契约/传输边界/共享模型与历史的设计约束不变，未来手机端等可以按入口接入；允许模型与历史共享的方向保留。
- 建设 TUI npm 一键发布能力；bootstrap 简易聊天 TUI 的 MIT、实现及验证后发包已获授权，当前结果见首发状态/发布台账。后续交付按路线图 r7 和各轮实际状态推进。独立实现边界有效。

## 首版建议，待审阅

从自有 Agent Core + TUI 开始：模型配置与流式对话；读取/搜索文件；预览和审批后写入；受控终端命令；取消与有界输出/上下文预算；会话保存和恢复。

团队、浏览器、Computer Use 和定时任务进入当前交付范围。TUI 的三种权限模式为仅可查看、工作区内修改和完全权限。原生移动 App 与全部云 Provider 从未自动纳入范围。

## 待决定

目标用户和差异化流程、首个模型协议、第一阶段工具集合、产品目录/包边界、UI/测试框架、配置/历史格式、跨端身份与凭据策略、后续产品版本与完整发布门槛，需对应迭代明确；bootstrap 采用 MIT/0.1.0。

验收条件应从自己的行为需求定义，例如“拒绝写入后磁盘不变且会话可继续”，不照搬旧私有源码、内部协议或系统提示词作为规格。

本轮补充的完整能力范围和验收见 [能力矩阵](agent-capability-matrix.md)，交付与命令约定见 [npm 发布方案](npm-release-plan.md)；首阶段闭环不代表最终只做首阶段功能。
