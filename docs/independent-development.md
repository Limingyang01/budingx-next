# 独立实现与复用边界

## 起点

新仓库有助于记录来源和开发过程，但复制旧源码后改名、删除 Git 历史或逐文件 AI 改写，不自动改变来源与许可。工程隔离不能单独作为法律洁净室认证。

旧仓只读保留，不把它设为新产品的代码依赖、运行回退路径或构建输入。实施阶段的规格应来自用户需求、公开协议、可适用许可的文档/SDK和新编写的验收测试。

## 可迁入的条件

每个候选模块记录：来源/revision、作者/许可证据、直接与传递依赖、保留/适配/重写决定、适用范围和验证。新建文件名、近期 Git 日期或“由 AI 生成”不单独证明可直接复用。

- 有明确许可的第三方库和开发技能，按其许可保留声明与必要材料。
- 自有且可独立分发的界面、宿主与工具，审计依赖后逐项迁入。
- 来源不清或耦合旧核心的代码，先隔离，不作为可发布实现。
- 原 Agent 循环、提示词、权限/上下文/全局状态、内部 SDK/type 文件和 bundle 不直接迁入。

## 数据与开发过程

旧模型配置和历史属于保护对象，不是可重建缓存。本次没有导入。将来应明确数据边界，使用只读读取、备份、前向迁移、旧 fixture 和未知字段保留验证；不直接覆盖旧配置目录。

独立实现可以使用公开模型 API/SDK，但必须按各自许可和服务条款处理。接入某模型与再发行该厂商的 Agent 程序源码是不同范围。

## 发布前需要的证据

来源台账、依赖与第三方声明；无旧源码/旧 bundle/旧 CLI 回退；干净环境的实际制品安装与核心行为；权限拒绝/取消/恢复；数据兼容；项目许可证与准确的发布内容清单。

代码相似度、字符串搜索和通过单元测试只能提供部分证据，不能替代来源审计。实际发行授权应按材料及适用法律核对，必要时由专业人士审阅。
