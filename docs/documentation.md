# 文档和需求记录约定

## 身份与范围

明确区分 USER_CONFIRMED、MODEL_PROPOSED、OPEN；文档头标识 draft/approved/superseded、范围和有效版本。用户批准、代码实现、验证通过、Git 发布和产品发布分别记录。

正式多步骤功能保存需求、中文设计/计划及 STATUS，无需英文版本；设计文档是正式 SDD 唯一常规人工审阅点，批准后计划、实施、测试与交付自主推进并在各阶段完成后本地提交（提交说明中文）。迭代汇总与功能 STATUS 是进度入口和断线续接依据，每阶段完成时同步更新；迭代进度维护见 [SP 管理说明](../SP/README.md)。小修复用最小方案和真实回归，不生成空模板。已有同版设计与授权继续有效，修正排版不重开审批循环。仅因文件已存在不能视为获批。

本项目按 SP 迭代版本号及具体功能/优化目录管理，没有需求 ID。统一使用 [SP 管理说明与模板](../SP/README.md)，总安排见 [迭代路线图](iteration-plan.md)。现行路线图 r8 连续使用 SP001–SP016；各轮状态以对应汇总为准，旧规划编号按当时的路线图解释。未归属迭代的材料可放 `docs/requirements/<slug>/`，归档规则见 [SP 约定](../skills/buding-sdd/references/sp-records.md)。

## 内容与证据

设计记录责任、复用依据、调用/事件边界、状态归属、失败/权限/取消/恢复、消费者和验证方式；计划写明确文件、接口、依赖、步骤和预期结果。未来目录/框架未决定时标 OPEN，不伪造实现路径。

验收使用稳定 AC ID，描述输入/动作/可观察结果。报告记录真实命令、cwd、输入 revision/环境、执行数量、PASS/FAIL/SKIP、原始日志位置和限制。无执行数据为 UNVERIFIED；历史成果保留历史身份，不移植成新仓通过证明。

源代码/架构变化同步有关文档；历史参考标明被替代方案和现行入口。日志、依赖、截图临时件和覆盖率原始产物放忽略目录，凭据、真实会话和用户身份不进入文档。

## 产品说明书同步

根目录 [产品说明书](../PRODUCT.md) 是面向使用者的单份事实入口，含产品版本号、按迭代归类的功能表、使用说明、限制与版本历史。

- 触发：任何改变用户可见行为、命令、配置、按键、数据路径、依赖、版本或能力范围的产品变更（代码或文档），无论大小。
- 必改章节：「版本与功能」「使用说明」「已知限制」「版本历史」中受影响的条目；新增或结束一项能力时同步更新按迭代归类的功能表，并把该迭代在表中的状态改成实际状态。
- 交付记录里必须写明本次更新了说明书的哪些条目，或写「说明书无需更新」及理由；不得默认跳过。
- 说明书只写已核实的事实：未实现、未验证和计划中的内容分别标注，不把计划写成已交付。
