# 技术栈与验证路由

本仓已有 src/tui 简易聊天预览（Node >=22.18、TypeScript、readline、Node test runner），完整 Agent 尚未实现。产品源码统一 src/，不引入 Bun；后续各端框架与 Core 协议尚待设计。旧仓 React、Ink、Vitest、Electron、路由或命令不构成本仓事实。

当前命令只用于技能维护，先看根 `package.json` 与 [开发指南](../../../docs/development.md)。技能维护测试通过不能证明 Agent、UI、Provider 或安装包可用。不得编造 `check:server`、`check:desktop`、产品 test/build/start/coverage 脚本，也不为运行历史命令安装整套旧依赖。

## 产品存在后如何定位

1. 先读 [AGENTS.md](../../../AGENTS.md)、[架构方向](../../../docs/architecture.md) 和实际包清单。
2. 核对所属包 package/lock、engines、入口、测试配置、依赖与最近测试，记录实际 cwd 与命令。
3. 区分产品行为、开发工具和 fixture；包之间不借用 node_modules 或配置来掩盖版本冲突。
4. 协议两端、存储、宿主与安装资源按实际实现核对，不预设单进程或共用 Agent。

## 责任与证据（待实现时的选择规则）

| 表面 | 最小证据 | 额外边界 |
| --- | --- | --- |
| 纯逻辑/状态机 | 输入输出、错误和取消单测 | 不为枚举纯逻辑启动服务 |
| Provider/协议 | 请求、响应、流分块、工具参数与取消 fixture | 真实上游可用需 live 验证 |
| Agent/工具/权限 | 可观察状态转换、授权和工具结果 fixture | 真实执行、停止、恢复另做隔离 smoke |
| 进程/服务/通信 | 真实测试实例、就绪、超时、隔离与清理 | 单连接不证明全客户端链路 |
| TUI/GUI/状态/API 客户端 | 逻辑、交互、请求形状 | 实际终端或浏览器证明布局/输入/滚动 |
| 持久化 | 旧 fixture、前向迁移、备份、未知字段保留 | 旧数据导入需另行授权与设计 |
| 宿主/安装/制品 | 生命周期、入口、资源路径 | 仓库外当前平台安装/运行 smoke |
| 文档/技能/维护工具 | 链接、frontmatter、生成入口与适用工具回归 | 不运行不存在的产品门禁 |

普通本地迭代运行最近的有意义检查；高风险或 PR/合并/发布才按届时合同补全适用门禁。不降低覆盖率阈值掩盖失败，未来引入门禁后在这里记录真实路由。跨层证据分开，旧仓成绩不得导入新仓结论。

## 隔离与集成核对

测试使用临时目录/配置根、测试端口和自己启动的进程，核对所有消费者确实使用隔离根。拒绝读取或清空真实密钥、聊天、MCP、技能、插件与账号状态。存储变化需迁移、备份、未知字段保留和旧 fixture；没有可执行验证入口应先补齐，不能宣称兼容。

依赖变更核对所属 package/lock；契约变更核对两端与 fixture；打包变更核对入口、资源和实际平台。迁移技能保留许可、版本/哈希和相对引用，不把旧绝对路径、系统提示词或内部 SDK 类型带入新产品。
