# v0.5.0 · SP005 长会话与数据可靠性

状态为 **PREPARED**（尚未发布）。本版把长会话与数据可靠性带进 TUI：会话可以落盘、可以跨进程恢复，长上下文会被压缩并保留关键约束，失败会给出明确原因与可定位的错误码。

- 新增会话转录持久化：会话内容写在 `~/.budingx/sessions/<会话ID>/` 下，转录逐条追加（每条一行），另有会话元数据与写锁文件。写入采用「临时文件 + 落盘 + 改名」的原子方式，失败时保留原有内容；损坏文件被隔离并保留 `.bak` 备份而不是删除；文件版本比当前程序更新时只读拒绝，不会被覆盖。
- 新增跨进程恢复：`/resume <会话ID>` 只装载历史消息，**绝不重放**任何工具调用；结果未知的工具调用会列为「需核对」并保留 `needs_review` 状态，由你确认后再决定是否重做；未知 ID 会明确报错，不会静默开出一个空会话。
- 新增上下文预算与压缩：估算用量超过预算阈值（上限的 85%，扣除预留输出后计算）时，较早回合被整体丢弃并替换为一条保留摘要。摘要有意保留用户明确提出的约束（最多 8 条，取最近）、当前计划与尚未完成的工具调用状态；被压缩掉的未完成工具调用替换为一条明确的「结果未知」占位，绝不伪装成成功。压缩后仍超预算时显式给出上下文超限原因，而不是静默截断。
- 新增项目与会话记忆：项目记忆按工作区根目录生成稳定键，写在 `~/.budingx/memory/projects/<项目键>/MEMORY.md`；会话记忆写在 `~/.budingx/memory/sessions/<会话ID>/MEMORY.md`。两处目录不同，一个项目看不到另一个项目的记忆，同级会话之间也互相看不到；疑似密钥内容会被拒绝写入；记忆不会写进你的项目目录。
- 新增四个命令：`/sessions` 列出已保存会话（会话 ID、标题、更新时间、回合数）；`/resume <会话ID>` 恢复历史；`/context` 显示上下文预算（估算用量、上限、预留输出、压缩触发阈值与逐条消息占用）；`/memory` 查看记忆条目，`/memory <project|session> add <标题>：<正文>` 写入一条记忆。
- 新增两级工具空转熔断：同一工具连续失败或反复重试同一签名时显式停机，终态错误码 `BUDINGX_CORE_010`，避免长任务在失败里空转到超时。
- 新增稳定错误码与失败定位：上下文超限 `BUDINGX_CORE_007`、压缩熔断 `BUDINGX_CORE_008`、恢复需核对 `BUDINGX_CORE_009`、存储写入失败 `BUDINGX_STORAGE_005`、会话被锁 `BUDINGX_STORAGE_006`；回合失败会给出错误码与失败位置，可在会话转录里按回合定位。
- 观测补强：provider 流式请求显式请求用量并解析末尾 usage 帧（端点不认时自动退回一次），模型观测带真实 token 数；工具观测现在带输入参数与结果，可以在 Langfuse 里直接判断工具调用是否合适。
- 修复：后台任务终态后释放子进程 stdout/stderr 读端——被终止的孙进程仍持有写端时句柄不收敛，`node --test` 会一直等事件循环清空（实测卡住 12 分钟）；另放宽 TUI 渲染回归用例的墙钟预算（20000ms → 90000ms），只放宽时间不放宽断言。

限制与未验证项：真实模型的**长会话压缩**（需用真实模型填满上下文预算才会自然触发压缩）仍为 UNVERIFIED，当前以真实 HTTP 请求体证据覆盖压缩内容，恢复条件见 [SP005 验收报告](../SP/SP005/test-report.md) §4；`/context` 与会话选择器的像素级观感待 SP006 可视化验收。转录与记忆写入失败时回合结果仍留在内存、进程退出即丢失——这属于「明确报错」而非「静默成功」（`BUDINGX_STORAGE_005`）。普通命令仍因缺少已验证的执行隔离后端而 fail-closed（同 0.4.0）。

升级方式：`npm install -g budingx@latest` 升级，再用 `budingx --version` 核对 0.5.0。
