# v0.9.1 · SP009

Status: PREPARED — 待维护者在 GitHub Actions 手动触发发布。

本版是 SP009 的补丁迭代，按用户反馈把主循环、上下文管理、子代理与技能与参考仓对齐。

## 变更

- **主循环不再硬停**：交互会话移除固定的 32 回合上限，只要模型持续返回工具调用就继续（对齐参考仓交互模式不传 maxTurns）。无头模式新增可选 `--max-turns <n>`（仅无头生效），达到上限以 `error_max_turns` 收尾；未设置则无上限。完成声明连续缺证据时改为有界重试（3 次），避免无限循环。
- **上下文窗口动态化**：窗口不再写死 200k。优先级为 `BUDINGX_CONTEXT_WINDOW` > 模型档案 `contextWindow` > 服务端 `/models` 报告的 `context_length`（等字段）> 默认 200k。`/models` 拉取模型列表时一并读取窗口，大窗口模型按真实值调高；自定义模型可在面板填写「上下文窗口」。
- **自动压缩默认启用并改模型摘要**：交互会话默认接入预算，压缩触发点改为「窗口 − 13k 缓冲」（对齐参考仓）。自动与手动 `/compact` 都会先调用模型把被裁剪回合浓缩成 `<compacted_summary>` 续作摘要，失败时回退确定性裁剪；约束/计划/工具状态保留项不变。
- **子代理对齐**：默认不再有 token 预算上限（仅显式 `tokenLimit` 启用），回归「子代理因预算中断」的问题。后台子代理终态通知按系统消息渲染，原始 `<task-notification>` XML 仍送达模型但不再当作「用户输入」展示；队列预览也用简洁文本。
- **技能多级别与创建/刷新**：技能级别改为 用户级 > 项目级（从当前目录向上至 git 根）> 内置级，同名用户级优先（对齐参考仓首胜顺序）；frontmatter 扩展键（`when_to_use`/`argument-hint`/`allowed-tools`/`context`/`user-invocable`）被解析保存。新增内置 `/skillify` 引导把可复用流程固化成 `SKILL.md`，以及 `/reload-skills` 命令按需刷新技能（不轮询）。

## 兼容性

- 0.9.0 的配置、会话、技能与模型档案格式全部向前兼容；`contextWindow` 为可选新字段，旧档案按自动解析处理。
- 同名技能冲突规则由「项目级覆盖用户级」改为「用户级优先」（参考仓语义）；依赖旧规则的技能建议改名或调整级别。
- `SUBAGENT_MAX_TURNS` / `SUBAGENT_TOKEN_LIMIT` 仍导出，但不再作为默认值。
- 无头 `--max-turns` 为新增可选参数，默认行为（无上限）与参考仓一致；既有脚本不传该参数时不会改变结果。
- Node.js 版本要求不变（>=22.18）。

## 升级

- `npm i -g budingx@0.9.1`（或你使用的安装方式）。
- 升级后无需迁移配置；如需固定窗口，可在 `/models` 编辑对应档案的「上下文窗口」，或用 `BUDINGX_CONTEXT_WINDOW` 临时覆盖。
- 旧会话可继续 `/resume`；压缩记录会带新的摘要消息，不影响恢复。

## 已知限制

- 子代理默认无预算，长任务依赖工具失败熔断、上下文溢出恢复与用户中断；如担心失控可显式设置 `tokenLimit`。
- 模型摘要压缩在极端小窗口下会回退确定性裁剪（不发摘要请求），摘要质量取决于模型。
- 技能级别的 managed/plugin/MCP 级别未实现（本仓尚无对应体系）；技能的模型自动触发与 per-skill `allowed-tools` 强制留待后续。
- `/help` 全屏下超长帮助只渲染可见部分（滚动查看的覆盖层因终端高度限制，长列表会被裁切）。
