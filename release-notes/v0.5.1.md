# v0.5.1 · SP005 复审修复

状态为 **PUBLISHED**。2026-11-20 10:09:50（新加坡时间）通过 GitHub Actions OIDC 发布，npm `latest` 已指向 0.5.1。本版是 0.5.0 的同轮 patch 修复，只改 0.5.0 的缺陷，不新增能力。0.5.0 发布后对 SP005 代码做了独立复审，发现并修复了写入锁互斥、记忆文件往返、压缩持久化与预算一致性等方面的问题。

## 修复

- **写入锁真正互斥**：会话写锁改为**排他创建**（O_EXCL）。0.5.0 用「先检查再写」的两步，两个进程可能同时通过检查并各自认为自己持锁；复审用 8 个并发进程复现，其中 6 个同时返回「已获取」。现在同一会话同时最多一个写入者。
- **释放锁只删自己的锁**：0.5.0 的释放逻辑无条件删除锁文件，未持有锁的进程也能删掉别人的锁，随后第三个进程还能再拿到锁。现在释放前核对锁内 pid，只有创建者能移除；陈旧锁仍要求显式强制接管，不静默删除。
- **修复项目记忆正文往返损坏**：0.5.0 把正文里以 `## ` 开头的行（例如 Markdown 二级标题）当成新条目，读回时正文被截断并凭空多出一条；标题里的换行还能伪造条目。现在正文中的结构行会被转义、读回时还原，标题压成单行并限长。**已有 0.5.0 写坏的记忆文件不会被自动删除**，仍按损坏隔离规则保留原件与 `.bak`。
- **真正检测记忆文件损坏**：0.5.0 的损坏检测分支不可达，所谓「保留原件 + `.bak` 备份」实际没有发生。现在无法解析出任何条目但存在内容的文件会被判为损坏：保留原件、旁存 `.bak`、拒绝继续写入并在 UI 报出原因。
- **减少凭据误判**：0.5.0 的通用 `键: 值` 规则会把「password: none」「token: not configured」「api_key = variable」这类正常工程笔记判成密钥并拒写。现在只有真正像密钥的值（混合大小写/数字/符号且不是占位词或引用变量）才会被拒绝；`sk-`、`ghp_`、`AKIA`、`Bearer`、PEM 等特征模式仍会拒绝。
- **压缩保留项不再撑爆预算**：0.5.0 在「保留的约束本身超过预算」时仍返回「压缩成功」，把超限请求发给模型。现在保留项按预算裁剪，压缩后仍然超预算会明确提示而不是静默下发。
- **压缩结果写入转录**：0.5.0 只把压缩写回内存、转录只记一条备注，导致 `/resume` 恢复出压缩前的完整历史，压缩被静默撤销；同一会话在重启前后上下文会不一致。现在压缩会写入可重放的转录记录（最终顺序、合成消息、被丢弃的消息 id），恢复时重放，得到压缩后的历史。
- **统一预算阈值**：`/context` 显示的预留输出与触发阈值和会话实际使用的数字不一致（0.5.0 中 `/context` 用 0 作为预留默认值，会话用上限的 1/4）。现在两侧读同一处归一化预算与阈值函数。
- **工具熔断计数按回合重置**：0.5.0 的计数跨回合累积且从不重置，不相关的失败会在后续回合被误判成空转；「同参数」签名直接比对原始 JSON，换键序或空行即可绕过。现在每回合重置，签名在解析 JSON 后按稳定顺序序列化。
- **恢复会话沿用原权限模式且不升权**：0.5.0 实现了降档函数但生产路径从未调用，录下的权限模式也没被读取。现在 `/resume` 会应用会话记录的权限模式，并且绝不因为恢复而提升档位。
- **`/memory` 缺少分隔符的提示修正**：`/memory project add 没有冒号` 在 0.5.0 中会把整串当成标题、正文为空，用户看到的是误导性的「正文不能为空」。现在直接给出用法提示。
- **原子写先收紧权限再改名**：临时文件此前以默认权限创建、改名之后才收紧，存在一段可被其他主体读写的窗口；会话元数据文件则从未收紧。现在临时文件在改名之前就设为 0600 并收紧 ACL。

## 已知限制（未在本版修复）

- **溢出后的强制压缩**在历史已被裁到只剩当前消息时无法再压缩，此时会明确报出「无法压缩」并终止回合，而不是假装重试。这是预算过紧时的固有限制，错误原因可定位。
- **恢复后的「需核对」仍是提示**：存储层不会重放工具调用，但如果模型在后续回合自行重新发起同一操作，当前版本不会二次拦截。请按 `/resume` 的提示先人工核对。
