## 多模态上下文（MM-01…10）

- 图片粘贴：Windows `alt+v`、其他平台 `ctrl+v`；`ctrl+v` 在剪贴板只有图片时自动回退为图片附件。
- `/image [路径]`：终端无关的图片附件入口——读剪贴板图片或指定路径，不依赖按键（VS Code 等宿主会吞掉 `alt+v`）。
- 路径附件：引号包裹、反斜杠转义、中文与路径紧贴均可切分；URL 不当作本地图片；同一路径只附件一次。
- 小图直通与缩放：未超限的调色板/灰度/16-bit/隔行 PNG 原样附件；超限 PNG 用纯 JS zlib 级联降采样（8000→2048→1568），5MB base64 / 8000px 阈值。
- 图片读不到时明确报错且保留输入正文（不再清空已写内容）。
- `~/.budingx/image-cache/<session>/<id>.<ext>` 私有缓存（0700/0600，LRU 200）。
- 能力前置拒绝（`vision: false` 不发请求）、错误驱动降级（拒图 → 剥离最近图片 → notice → 无图重试一次）、媒体上限 100 张丢最旧。

## 用户可见的缺陷修复（图片链路）

- 中文句子紧贴图片路径时整句被当成一个 token，导致整轮消息被阻塞、模型收不到内容 → 改为按扩展名定位并止于中英文标点。
- 调色板/灰度/16-bit/隔行 PNG 即使只有几百字节也被拒绝 → 未超限直接原样附件，仅需缩放时才解码。
- 剪贴板只有图片时 `ctrl+v` 无任何反应 → 回退为图片附件（`alt+v` 行为不变）。
- 图片读取失败会清空并吞掉用户已写正文 → 失败时原文写回输入区。
- VS Code 集成终端把 `alt+v` 当作键位 chord 前缀拦截，按键根本进不到程序 → 新增 `/image` 命令作为终端无关入口，并在 `/help` 中列出。
- 连按粘贴键会把同一张图重复挂成 `[Image #1][Image #2]` 并上传两次 → 按内容哈希去重，复用已有占位并在提交时只发送一次。
