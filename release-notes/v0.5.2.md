# v0.5.2 · 长会话渲染优化与上下文可见性

状态为 **PUBLISHED**。2026-11-20 11:23:43（新加坡时间）通过 GitHub Actions OIDC 发布，npm `latest` 已指向 0.5.2。本版是 SP005 的同轮优化补丁，不新增会话模型，只解决长会话卡顿并把上下文用量与推理强度显示出来。

## 长会话卡顿与卡死

复现方式：在 600～2000 条历史的会话里让模型流式输出一段长回答。0.5.1 下同场景耗时 **1806ms**、长回答时可达数秒；本版 **997ms**（约 1.8 倍），2000 条历史 + 24k 字符流式的最差帧间隔 **51ms**，没有出现秒级冻结帧。

- **流式输出不再每帧全文重排**：此前每个流式片段都会把整段回答重新分词折行，代价随回答长度平方增长（20k 字符时 20 个片段就要 273ms）。现在只累积原文，渲染时按"已完成段落 + 末尾未完成段落"增量解析，已完成段落的结果被复用；同一对象身份让记忆化真正生效（此前每帧新建对象，缓存全部失效）。
- **移除无人消费的中间数据**：渲染器早就不再读取折行结果与静态行缓存，但 reducer 仍每帧复制它们，长会话下是纯浪费。已删除这两个字段。
- **虚拟列表按参考实现收紧**：上下预渲染从 10 行提升到 80 行，单帧新增挂载上限 300 条、每次提交最多新增 25 条，避免一次滚动就挂载数百条消息造成长时间同步阻塞；窗口宽度变化时高度缓存按比例缩放而不是清空，避免缩放后整屏重新测量。
- **流式片段按帧合并**：模型每毫秒可能推送多个片段，此前每个片段都触发一次整棵树重渲染。现在合并为每帧一次（约 16ms），任何非文本事件（完成、工具、错误）都会先结算已缓冲文本，顺序不变。
- **共享分词器**：折行不再每次新建 `Intl.Segmenter`。

## 上下文用量与推理强度

- **状态栏常驻上下文用量**：左下显示已用 token；配置了窗口上限（`BUDINGX_CONTEXT_WINDOW`，单位 token）时同时显示百分比与"已用/上限"，达到 80% 变黄、95% 变红。数字优先取模型汇报的真实用量，缺失时用本地估算并标注"（估算）"。
- **状态栏常驻推理强度**：右下显示 `⊙ low|medium|high · /effort`。
- **`/effort [low|medium|high]`**：查看或设置推理强度，下一次请求生效。未显式设置时不下发 `reasoning_effort`（不少兼容端点遇到未知字段会 400）；即便服务端拒绝该字段也会自动退让一次后重试，不会让整轮失败。也可用 `BUDINGX_REASONING_EFFORT` 指定初始值。
- **`/context` 在没有配置预算时也能用**：至少报出已用 token 与数据来源，不再直接报"未接入"。

## 交互式 TUI 默认开启会话持久化

0.5.0／0.5.1 的 `/sessions`、`/resume`、`/context`、`/memory` 在交互式 TUI 里其实没有数据源（运行时未开启持久化）。本版让交互式 TUI 默认开启会话转录与项目记忆，四个命令与上下文用量由此可用。

会话内容写在 `~/.budingx/sessions/<会话ID>/`、记忆写在 `~/.budingx/memory/`，目录与文件只对当前用户可读写（与 0.5.0 起的规则一致）。如果不想落盘，可在启动前把 `BUDINGX_HOME` 指向临时目录用于试验。

## 验证

- 新增用例：流式增量不做全文重排（400 片段 × 80k 字符断言耗时上限）、完成后回答只入转录一次、虚拟范围有界、token 文本格式、真实用量记录与清空重置、effort 随请求下发、状态栏上下文与 effort 显示、`/effort` 改完即时反映、真实 CLI 进程对本地流式服务的端到端往返（内容完整 + effort 下发 + 退出码 0）、2000 条历史长回答压测（最差帧间隔上限）。
- 保持既有行为：审批、权限三档、计划与待办卡片、转录搜索、`/clear` 等既有用例全部通过。

## 已知限制

- 上下文百分比只在显式配置窗口上限时显示；程序不替用户猜模型窗口大小。
- 超高帧率下的极端长回答（十万字符级单条消息）仍受终端本身重绘能力限制，本版只保证不出现秒级冻结，不承诺固定帧率。

升级方式：`npm install -g budingx@latest`，再用 `budingx --version` 核对 0.5.2。
