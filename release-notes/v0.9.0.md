# v0.9.0 · SP009 · TUI 独立交付和 npm 发布工程

Status: PREPARED — 已合入 master（`10704ab`），等待维护者在 GitHub Actions 手动触发发布。

## 变更

- **技能触发不再回显提示词**：`/<skill>` 现在把技能正文作为上下文块送达模型（请求侧包装为 `<skill name="…">`），会话里只显示 `/<skill>` 回显与「技能 /skill 已加载」提示；恢复会话后同样只显示「上下文 · skill:<名称>」。`/skills` 与 `/help` 仍列出技能名和描述。
- **`/export` 可以选择会话**：交互终端打开会话选择面板（当前会话 + 已保存会话，↑↓ 选择、Enter 导出）；`--session <会话 id>` 导出指定会话；无头/脚本模式不带参数仍导出当前会话。导出内容来自所选会话自己的历史。
- **发布工程**：发布编排抽为可注入 npm runner 的状态机（`publish-core.mjs`），判定层集中在 `pipeline.mjs`；新增通道规则（预发布禁止 `latest`、稳定版走其他通道需在发行说明声明 `dist-tag:`）、失败分类（gate/local/auth/permission/conflict/network/unknown）、发行说明五小节结构校验。
- **恢复命令**：`npm run release:resolve -- --version <版本>` 只读判定远端状态（已发布/未发布/内容不一致/未知），不上传、不 bump、不改 dist-tag。
- **一致性门禁**：`npm run version:check` 核对包清单、台账、发行说明与说明书/README/状态文档的版本；`npm run test:install` 与 `npm run test:upgrade` 用真实 npm 验证干净安装、覆盖升级、旧数据兼容、卸载与回退；交叉验证门禁新增 `version:check` 与 `test:upgrade` 两步。
- **npm 调用隔离**：发布相关 npm 调用统一使用显式缓存目录，不再依赖用户配置区的可写性。
- **修复：全自动档位被工作区边界误拦**（用户报告）：完全权限档位下读取/修改工作区外文件不再报 `BUDINGX_PERMISSION_001`；仅可查看与工作区内修改两档保持工作区边界；`~/.budingx` 数据根、凭据形状文件与 `.git` 写入保护的规则不变。

## 兼容性

- 不改变产品运行时行为、三档权限模式、Provider 协议与数据格式；`~/.budingx` 布局不变。
- 技能会话中旧消息（此前写入的 `# Skill /…` 用户消息）保持原样，不做迁移。
- `/export` 非交互默认行为保持导出当前会话；新增的 `--session` 与选择面板是增量能力。
- **行为变更（用户确认）**：全自动档位不再受工作区边界限制。此前依赖该拦截做防护的用户应改用仅可查看/工作区内修改档位，或保留 `~/.budingx` 与凭据形状文件的地板（仍不可读写）。工作区外写入不进入会话撤销快照。
- 发布台账结构不变（schemaVersion 1）；新增命令均为维护者工具，不影响普通使用。

## 升级

```powershell
npm install -g budingx@latest
budingx --version   # 期望 0.9.0
```

升级只替换程序文件，`~/.budingx` 的配置、凭据、会话与记忆保持不变；旧配置按迁移规则就地升级并保留 `.bak` 备份，未知字段不丢失。回退可安装指定旧版本（如 `npm install -g budingx@0.8.0`）；卸载默认保留数据。

## 已知限制

- 覆盖升级门禁的旧版本包由「当前源码 + 已发布版本号」构造，验证的是安装与数据路径，不是重新构建的历史版本。
- 真实 registry 上的回退安装与 dist-tag 移动未在本轮取证（需发布授权）。
- macOS 未实测；Linux 的覆盖升级/卸载/回退场景尚未执行（CI `verify` 只覆盖打包与安装 smoke）。
- `version:check` 只覆盖列出的六个文件，不检查正文语义。
- 技能恢复视图的实机渲染由上下文块机制覆盖，未单独做像素级 TUI 断言。
