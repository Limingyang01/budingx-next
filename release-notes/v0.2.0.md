# budingx 0.2.0 · SP002 模型与会话闭环

状态：PUBLISHED（2026-11-17）。维护者手动触发 GitHub Actions 运行 #7，Windows/Linux 验证及 npm OIDC 发布全部成功，官方 latest 已指向 0.2.0。

## 用户可见变化

- 新增模型档案添加、编辑、删除、默认模型、工具能力标记和连接验证。
- `/provider key NAME` 隐藏录入或更新 API Key；模型配置与凭据分文件存入当前用户的 `~/.budingx`，密钥绑定档案及端点主机。
- `/model NAME` 保留会话，下一回合使用新的模型、端点和密钥；修改或删除活动档案会同步刷新配置。
- Ink 8 多行对话界面，中文/ASCII 首屏、流式回答、输入历史、粘贴、光标、审批卡和基本 resize 重排。
- Esc 打断、执行中输入排队、回合边界命令串行执行；`/clear` 同步清除模型上下文及可见会话内容。
- Provider 支持 tool_calls 碎片、有界重试、Retry-After、取消、超时与错误分类；工具 schema 完整传递，无参数工具使用显式空对象 schema。
- 根目录 `npm run start` 仅供本地测试，自动加载可选 `.env.e2e.local`；正式安装的 `budingx` 不加载该文件，真实环境自行配置。

## 从 0.1.1 升级

- 包名和命令仍是 `budingx`，Node.js 要求仍为 `>=22.18.0`。现在可用 `npm install -g budingx@0.2.0` 更新，并用 `budingx --version` 核对。
- `BUDINGX_BASE_URL`、`BUDINGX_MODEL`、`BUDINGX_API_KEY` 及已有启动参数继续可用；优先级为参数 > 环境 > 默认档案。
- 包内部 bin 从 `dist/cli.js` 改为 `dist/tui/cli.js`。正常 npm 安装会更新命令 shim；自行引用旧 dist 路径的脚本需要调整。
- 新增运行时依赖 Ink、React、string-width；通过 npm 正常安装，无需源码、TypeScript、其他客户端或 Bun。
- 空闲 Ctrl+C 改为连续两次退出；执行中一次 Ctrl+C 为取消。审批卡可用 y/n，卡上 Esc 拒绝当前请求并继续。
- 0.1.1 的环境变量配置不会自动保存为档案。不要将测试文件或凭据复制给其他人；不导入、读取或迁移 `~/.claude`。
