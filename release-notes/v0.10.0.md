# v0.10.0 · SP010

Status: PREPARED — 源码已就绪，等待维护者在 GitHub 手动触发 npm 发布。

## 变更

- **中期编码效果检查（SP010）**：新增可执行的中期任务集 `cp-v1`（18 条基本编码 + 12 条保护用例），每条任务带独立快照与 SHA-256 清单；评估器回合上限改由版本化预算档提供（B/A/P），不再用固定 8 轮截断测量对象。
- **取消恢复整题评分**：CAN 题次按「取消 → 产品恢复入口 → 续跑」两个回合计量，复用同一份预算并只计一次整题结论；恢复回执、首回合消息匹配与副作用计数都进入判定。
- **报告统计口径**：按类别给出任务等权完成率与 Hoeffding 95% 区间、延迟 p50/p95、token 与费用估算；盲测条目只落盘状态与分类；报告标注「中期结果」并禁用替代性措辞。
- **运行身份与续跑**：每个批次冻结候选 SHA、题集与快照摘要、模型、预算档与重复次数；任一字段变化即拒绝续跑。
- **保护用例确定性验证**：PROT-01…12 逐条驱动真实产品路径（凭据地板规则、网页内容权限档、目录穿越与 junction 越界、审批拒绝后继续、进程树终止、输出截断、单写者拒绝、旧目录与凭据隔离、无关改动保留、残缺流诊断错误）。
- **主循环逐路径判据**：补齐工具回填、上下文溢出重试、输出达限与两种缺证续跑的取证用例；Stop hook 为旁听语义，相关参考出口按 GAP 登记。
- **TUI 行为修复**：正文被思考行拆开的问题已修复；单轮 `/compact` 手动压缩在空闲时可用且失败保留历史；新增旁路问答面板与中文退出恢复提示（`budingx --resume <ID>`）。

## 兼容性

- Node.js ≥ 22.18（不变），不引入新的运行时依赖。
- 权限仍为三档（仅可查看 / 工作区内修改 / 完全权限），用户数据根仍为 `~/.budingx`，不读取 `~/.claude`。
- 命令、按键与配置项无新增或改名；`/compact`、`/export`、`/skills` 等既有命令行为不变（手动压缩为修复）。
- 评估资产（`scripts/eval/`）只用于测量，不进入 npm 制品。

## 升级

```bash
npm install -g budingx@0.10.0
```

- 升级不改数据根格式，无需迁移；`~/.budingx` 下的既有会话、配置与凭据继续可用。
- 回退：`npm install -g budingx@0.9.2`。

## 已知限制

- 正式中期评测（30 题 × 3 次）需要 ≥90 次真实模型请求；本轮本地预算上限为 6 次请求 / 5 美元，只完成 1 条真实 Provider 冒烟，其余按「证据不足 + 恢复条件」记录，未标记为通过。
- 工具返回的图片目前只有元数据进入模型上下文，像素内容不进模型；该媒体缺口归 SP012/SP013。
- 本仓无团队、调度、浏览器与桌面控制原语；相关接入缺口见 [SP010 接入前置核查](../SP/SP010/core-reliability/readiness.md)。
- Stop hook 为旁听语义，参考实现的 stop_hook_blocking / stop_hook_prevented / hook_stopped 出口在本仓不存在，按 GAP 登记。
