# v0.8.0 · 多端架构入口与共享边界（SP008）

状态 **已准备（prepared）**（2026-11-22，npm `latest` 仍为 0.7.0，等待维护者触发 GitHub Actions 发布）。源码版本 `src/tui/package.json` = 0.8.0，发布分支 master。

本版固定 TUI、headless 与未来各端共用的**本地宿主契约**，并新增 `budingx serve` 入口（进程内 / stdio / WebSocket 三种传输）。同机共享边界、活动会话归属与崩溃恢复、凭据作用域与传输不泄密均以真实进程端到端验证。

## 宿主契约与传输边界（TB-01…08）

- 版本化 NDJSON 协议：请求 `{id,type,...}`、响应 `{id,ok,result|error}`；服务端主动帧 `hello_ok`、`event`（递增 `seq`）、`role_changed`、`fatal`、`pong`。
- 三种传输：进程内 `connectInProcess`、stdio `connectStdio`、WebSocket `startWsHost`/`connectWebSocket`（自写 RFC6455 帧、掩码、分片、ping/pong）。
- 请求类型：`hello`、`describe`、`history`、`submit`、`interrupt`、`approval`、`set_permission_mode`、`takeover`、`shutdown`、`ping`。
- 身份固定：`hello_ok` 返回 `protocolVersion=1`、`sessionId`、`workspaceId`、`clientId`、`role`、`scope`（固定 `local`）。
- 帧与错误边界：协议版本不匹配返回 `HOST_PROTOCOL_001` 并断开；重复请求 id 返回 `HOST_PROTOCOL_002`；单帧上限 1 MiB，超限先发 `HOST_PROTOCOL_005` 再关闭；畸形帧不影响既有连接。
- `interrupt` 在无活动回合时返回 `{interrupted:false}`，有活动回合时返回 `{interrupted:true}` 并以 `cancelled` 收尾；`history` 支持 `limit` 截断。

## 活动会话归属与崩溃恢复（SO-01…04）

- 单写者模型：`~/.budingx/sessions/<id>/writer.lock` 排他锁，首个连接是 `owner`；同进程第二连接或另一进程在活 owner 存在时启动均为 `observer`。
- observer 可读描述/历史、可收本进程实时事件；`submit`/`interrupt`/改权限/审批/接管一律以 `HOST_SESSION_003` 拒绝；`shutdown` 仍可用。
- 崩溃恢复：owner 被杀后锁变陈旧，需显式 `--takeover` 才成为 owner；活 owner 存在时接管被拒且原锁不变。恢复只装载历史，**不重放工具副作用**；结果未知的步骤列入 `needsReview` 并附 `warnings`。

## 共享数据与凭据作用域（SH-01…05）

- 配置并发安全：新增 `ConfigStore.update(mutate)`（锁文件 + 重读 + 原子写 + 超时错误码 `BUDINGX_STORAGE_006`），并发更新不丢配置。
- 转录尾行容错：并发写入产生的半行不计 `corruptLines`，共享历史读取稳定。
- 写锁检视 API：可读取 pid、创建时间与 active 状态，不删除陈旧锁。
- 凭据按 `(id,host)` 作用域存放；宿主不提供凭据读取接口，配置/描述只含 `apiKeyRef` 引用，三种传输的全部字节经断言不含 key 或 `credentials.json` 内容。

## `budingx serve` 入口与宿主扩展

- `budingx serve [--transport stdio|ws] [--session ID] [--takeover] [--host ADDRESS] [--port N] [--token TOKEN] [--home DIR]`；WS 只接受回环绑定且必须显式提供令牌（缺失退出码 2），令牌不隐式生成、不打印。
- owner 进程与交互 TUI 读取同一份 `~/.budingx/mcp.json` 与 `~/.budingx/hooks.json`：MCP 工具名 `mcp__<服务器>__<工具>`，默认需审批；hook `allow` 可跳过审批、`ask` 回到人工审批、`deny` 或退出码 2 阻断；`PreToolUse` 可改写工具入参，附加上下文进入模型请求；多 MCP 服务器并存互不串台。
- observer 只读历史，不启动任何扩展子进程；宿主关闭时先停会话再回收 MCP 子进程。
- 退出码：0 正常关闭；1 归属或运行时启动失败；2 参数、认证或绑定违规。

## 已知限制与未验证项

- **跨进程 observer 没有实时事件通道**：observer 只能读持久化历史，断线后无事件重放/续传。
- **WS 仅支持本机回环绑定**，明文 HTTP 升级只允许回环地址；令牌必须显式提供。
- **Windows 无法向 Node 投递可捕获的 SIGTERM**：强制终止会留下陈旧锁，需用 `--takeover` 恢复（属预期恢复路径）；POSIX 下 SIGINT/SIGTERM 与 EOF 走同一清理路径 → **PARTIAL**，恢复条件：在 Linux/macOS 上验证 SIGTERM 路径。
- **宿主事件无重放**：宿主不缓存事件，断线观察者重连只能重新 `describe`/`history`。
- 端到端使用本地 SSE fixture 验证协议与编排，**未用真实外部模型跑过 `serve` 回合** → **UNVERIFIED**，恢复条件：提供真实模型凭据后运行 `budingx serve --transport stdio` 并提交一次真实回合。
- MCP/hooks 用自模拟服务器与脚本验证，**未逐一验证真实第三方 MCP 服务器与 hook 脚本的兼容性** → **UNVERIFIED**，恢复条件：用真实 MCP 服务器与 hook 脚本各跑一轮。
- Desktop、VS Code、移动端、远程/H5 与 IM 仍在本版范围外，只保留通用宿主边界。
