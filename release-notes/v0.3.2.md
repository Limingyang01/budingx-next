# v0.3.2 · SP003 模型兼容与终端体验修复

状态：**PUBLISHED**。2026-11-18 已通过 GitHub Actions OIDC 发布，发布时 npm `latest` 指向 0.3.2。

## 本版变更

- 支持的交互终端启动后占满窗口，输入区固定底部，状态栏提示 Shift+Tab 切换权限模式。用 PageUp／PageDown 浏览会话。
- 终端标签从 `budingx` 更新为简短会话标题，进行中的回合显示实心状态点。标题取自首次有实际内容的问题，`/clear` 后重置。
- 一次配置供应商后，可在拉取结果中按空格多选模型并保存。选中已有档案按 A 可添加同组模型，沿用端点及 Key。编辑组内任意档案的共享字段会更新该组；删除单个模型保留共享凭据。同厂商的不同账号或套餐仍可分别配置。

- `/models` 新增 **MiniMax（中国站）**，预填 `https://api.minimax.cn/v1`。粘贴 Key 后可拉取模型。列表接口不可用时可选标注为建议的 `MiniMax-M3.1-Flash` 或 `MiniMax-M3`。
- MiniMax M3 系列连接探测使用能容纳思考的有界输出预算。若服务仅返回思考并耗尽该预算，面板提示已连接但没有正文。工具调用和普通聊天分别检验。同一档案的工具续跑会保留必要的 `reasoning_content`，切换档案时不会转发它。
- 阿里云百炼的 **按量付费** 和 **Token Plan** 模板分开。Token Plan 预填 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，使用对应套餐 Key。专属工作空间仍使用官方模型列表接口。套餐端点无列表接口时提供官方示例 `auto`，鉴权失败仍显示失败。已有不同地域、套餐或工作空间可用 Custom。

如需安装此历史版本，运行 `npm install -g budingx@0.3.2`，用 `budingx --version` 核对 0.3.2。已有档案保留，按需编辑端点和凭据。真实厂商账号尚未逐个验证。
