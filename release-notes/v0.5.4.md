# v0.5.4 · 联网搜索审批修复

状态 **PREPARED**（已准备，尚未上传 npm）。本版修复 0.5.3 引入的联网搜索审批问题，不新增能力。

## 修复

- **完全权限（全自动）下不再为联网搜索弹审批**。0.5.3 把 `WebSearch` 标记为「无条件必须审批」，绕过了三档权限判定，所以在完全权限档位下每次搜索都会打断，且与界面底部「全自动」的说明自相矛盾。现在联网搜索是一种独立能力（出网），按档位判定：
  - **完全权限**：直接执行，不弹窗。
  - **工作区内修改 / 仅可查看**：每次确认，但可以选择「本会话记住」，同工具不再反复打断。
  - 已保存的允许/拒绝规则、`.git` 与敏感文件的硬性审批不受影响。
- **审批卡选项编号与按键一致**。此前在「不能记住」的审批上只显示 `1 允许一次 · 3 拒绝`，2 被隐藏却没有重排，看起来像少了一个选项。现在这种情况下显示 `1 允许一次 · 2 拒绝（或 Esc）`，按 `2` 即进入拒绝；能记住时仍是 `1 / 2 本会话记住 / 3 拒绝`。
- **修正「已授权」的判定口径**。此前 `ToolContext.approved` 只在弹出审批框并被允许时置真，权限档位自动放行时仍为假，导致出网工具的自保护检查在完全权限下误拒。现在只要调用被授权执行（审批放行或档位自动放行）就置真；工具保留出网前的授权自检作为兜底。删除类工具的硬性审批不受影响。

## 行为变化提示

- 在完全权限档位下，模型调用联网搜索会**直接发送查询**（与读写文件、执行命令一致）。若你不希望查询外发，请切换到「工作区内修改」或「仅可查看」，那里仍会逐次确认。
- 联网搜索默认走 Bing；配置 `BUDINGX_TAVILY_API_KEY` 后走 Tavily。

## 验证

- 新增策略用例：完全权限放行、工作区修改需确认且可记住、仅可查看需确认、不影响执行与写入判定。
- 新增会话级端到端用例：完全权限下 `WebSearch` 完成且**零次审批**；工作区修改下**恰好一次**审批。
- 新增审批卡用例：不可记住时显示 `1/2` 编号，按 `2` 进入拒绝流程，且不再出现 `3`。
- 既有权限、审批与搜索用例保持通过。

升级方式：`npm install -g budingx@latest`，再用 `budingx --version` 核对 0.5.4。
